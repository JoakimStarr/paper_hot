# 选题中心「操作逻辑与引导」重构方案

## 背景与问题

PRODUCT_PLAN.md 的愿景是"把 AI 从分析单篇论文升级为陪伴整个选题流程"，选题中心是旗舰功能。但探索发现当前五步向导是**五个功能的堆叠**，12 个引导缺口：

1. 全模块没有"下一步"按钮（Step1 文案却说"点击下一步继续验证"——指向不存在的按钮）
2. 步骤条完成勾是假的：`done = n < current`（位置性），与内容产出完全无关
3. 验证报告里的新颖性/拥挤度/可行性评分从未被解析，数据库 `novelty/crowding/feasibility` 字段全闲置；`status` 状态机（待验证/已验证/已立项/已放弃）UI 从未展示
4. 验证完成后自动生成立项书，但只有一行不可点击的小字"见第 5 步"
5. 项目列表卡不显示状态和评分，五个入口（AI 推荐/一句话/热点/关注/空白）样式雷同，新用户不知区别
6. AI 产出完成后没有"接下来做什么"的跨步引导；Step3→Step4、Step2→Step3 的数据依赖只靠空态文案
7. Step4"提取线索"按钮无文献时静默禁用无解释
8. 检索关键词只对 IdeaWizard 来源的项目存在，其他来源无处补录
9. trends 页热点没有"转选题"入口（规划过未落地）
10. 删除项目用原生 confirm；英文导航还叫 "Topic Lab"
11. 后端 prompt 散落各 router：literature_review 有两套平行实现；验证每次全量重跑无缓存
12. 整个流程没有 onboarding，列表页首屏信息密度过高

**Skill 借鉴**（来自本机 academic-paper / literature-review / paper-audit / econometrics-skills 四个技能的设计模式）：
- **盲态预承诺评分**（academic-paper 生成器-评估器契约）：先让评审在未见证据前写下评分标准，再注入证据打分——防"先看证据再找理由"
- **[Script]/[LLM] 证据分离**（paper-audit）：统计结论由确定性查询产出标注，LLM 判断单独标注
- **显式"未找到的证据"声明**（literature-review）：禁止用沉默冒充"没人做过"
- **方法三元组**（econometrics-skills）：每方法 = 适用场景 + 数据需求 + 诊断清单 + 参考代码，正好注入 Step4
- **门禁 + 命名产出物**（academic-paper）：每步一个命名产出物，完成判定驱动引导

## 第一期：引导层（操作逻辑重构）

### 1. 完成度真实化
每步定义 Done 条件（前端 `STEPS` 配置加判定函数）：
- Step1: `title` 非空 && `research_questions ≥ 1`
- Step2: `validation_report` 存在
- Step3: 文献集 ≥ 3 篇
- Step4: `data_insights` 存在
- Step5: `proposal` 存在

步骤条按内容显示：✓已完成 / ●当前 / ○待完成（hover 提示"完成条件：xxx"），替换现在的位置性假勾。

### 2. 主线 CTA 与跨步引导
- 新增 `StepFooter` 组件：每步底部主按钮「完成本步，进入：XXX →」+ 次按钮"留在此步继续打磨"；Step5 主按钮变「完成，回到选题库」
- AI 产出完成后的跨步引导卡：验证完成 →「新颖性 X · 拥挤度：低 → [去第 3 步召回文献] [查看立项书]」；文献脉络完成 →「接下来：第 4 步提取数据线索」
- Step2 的立项书提示改为可点击链接（跳 `?step=5`）

### 3. 评分与状态激活（轻量版）
- 前端正则从验证报告解析"新颖性评分 X / 拥挤度：X"回填 `novelty/crowding`（现有 PATCH 已支持，不动 prompt）
- `ProjectList` 卡片加：status 徽章（待验证/已验证/已立项/已放弃，四色）+ 评分小条（新颖性 X/10 · 拥挤度），status 筛选下拉
- ProjectDetail 头部加 status 操作（标记已立项 / 暂时放弃 / 恢复），激活闲置的状态机

### 4. 检索关键词补录
`TopicProject` 加 `search_keywords` JSON 列（沿用 init_db ALTER 模式）；Step1 加关键词编辑器（增删），Step2/Step3 读取：优先 `search_keywords`，回退 `generated_topics[*].keywords`——解决"只有 IdeaWizard 来源项目才有检索关键词"的断裂。

### 5. 文案与细节修复
- 删除/改写误导文案（Step1"点击下一步"等）；Step4 禁用按钮加 tooltip 说明原因；删除确认换已有 `ConfirmModal`；英文导航 "Topic Lab"→"Topic Center"；i18n 中英补齐

### 6. 联动补全
- trends 页热点条目加「转选题」（复用 network 页已有模式，`source_type='keyword'`）
- Step2/Step3/Step5 关键处加 `openAssistant()` 悬浮助手按钮（助手已有每步人设和预设问题，只缺入口）

## 第二期：技能层（AI 重构，一期验证后做）

### 1. 技能模块 `backend/app/skills/`
- `registry.py`：技能路由表（名称 → 自包含模块），沿用现有 `ai_pending` 后台轮询机制
- 每个技能 = **prompt 模板 + 输入契约 + 输出 schema + 降级路径**（移植 econometrics-skills 的两层路由结构）

### 2. `validate` 技能（重构现有验证 prompt）
- 盲态预承诺：先让模型输出评分 rubric（什么算拥挤、什么算窗口），再注入证据打分
- 输出 = **JSON 头**（novelty 1-10 / crowding / feasibility / gate: pass|caution|avoid）+ markdown 正文；后端解析 JSON 头直接回填字段并驱动 `status→validated`（替代一期的前端正则）
- 正文强制段落：新颖性（[n] 引用）/ 拥挤度 / 机会窗口 / 风险与盲区（含**"未找到的证据"声明**）/ 差异化切入 / 结论
- [Script] 证据块：拥挤度统计、竞争地图由后端预计算后以"确定性证据"注入 prompt，与 LLM 判断分离标注

### 3. `method_playbook` 方法手册（注入 Step4）
内置 ~10 个经管方法条目（DiD、PSM-DID、IV、RDD、面板固定效应、合成控制、事件研究、文本分析/字典法、ML 预测、空间计量），每条 = 适用场景 + 数据需求 + 关键假设 + 必做诊断清单 + 参考 Stata/Python 实现（静态文本模板）。`data_insights` 生成时按选题关键词/子领域自动匹配注入对应条目。

### 4. `lit_review` 收敛
把 workbench `literature_review` 与 producer `/review` 两套平行 prompt 收敛为单一技能（输入契约不同则参数化），消除维护分叉。

### 5. 二期可选项（默认不做，需要再说）
- 评审人质询（3 persona 审稿人视角风险清单）
- 验证结果缓存 + 复验 diff（同一题目不重复计费，复验输出"新增竞品/空白是否仍成立"）

## 依赖说明
**零新第三方依赖**——全部用现有 FastAPI/Next.js 栈；方法手册代码示例是静态模板，不需要安装 Stata/R 运行时。

## 验证
- 后端：pytest 新增（评分解析、技能注册表、方法匹配规则、search_keywords PATCH），现有 82 个测试不回归
- 前端：`tsc --noEmit`
- 手工走查：新建项目（gap/热点/想法三来源）→ 五步全流程 → 列表评分/状态展示 → trends 转选题

## 交付节奏
一期一个可验证交付（引导层，前端为主 + 一列迁移 + trends 小改动）；二期两个改动包（validate 技能重构、method_playbook+lit_review）。每期结束跑全量测试。
